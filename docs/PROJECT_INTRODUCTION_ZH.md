# Delegate Control for ChatGPT 项目介绍

本文面向开源分享、项目演示与视频脚本策划，描述 0.1.6 已实现的候选功能，不把本机回归等同于最终用户验收。

## 一句话介绍

DCFC 是一个 Windows 桌面工具，通过 MCP 让 ChatGPT 将成果保存到你指定的本机项目目录，读取和更新已有文本，并统一管理多项目连接、权限边界和运行诊断。

## 为什么做这个项目

使用 ChatGPT 做研究、写方案、讨论产品或整理开发交接时，真正费事的往往是内容生成之后：复制正文、创建文件、选择目录、维护版本，再把更新后的资料提供给下一次对话。

同时处理多个项目时，这个问题更明显。你需要的不只是把内容写进电脑，还要知道写到了哪个项目、是否覆盖了刚修改的版本，以及连接出错时到底是哪一个环节出了问题。

DCFC 把对话成果和本机项目文件连接起来。ChatGPT 仍负责内容工作，DCFC 提供限定范围的工具，并管理背后的本机服务。

## 用户能做什么

用户先在桌面端配置项目。例如 ScreenCast、Realize 和 DCFC，各自设置稳定的 project_id、输出目录和独立端口。项目数量不限定为三个，但运行规模取决于机器资源。

连接完成后，可以要求 ChatGPT 将报告保存到指定项目，列出已有成果，读取一份需求文档，或者在交接记录末尾追加评审结论。已有文件支持追加、精确替换和删除文本片段，而不是每次都重新生成整份文档。

界面提供首页、项目管理、日志、连接设置、安装诊断和首次配置向导。用户可以单独启动/停止一个项目，或者启动/停止全部项目；正常共享链路下，停止一个项目不会把其他项目一起停止。

它适合开发交接、产品设计协作、研究报告整理、会议纪要和长期维护项目资料。它不是无限制地接管电脑，当前文件能力主要面向 UTF-8 文本。

## 技术上值得讲的四件事

### 一条共享连接与稳定工具目录

公共调用链是 ChatGPT Connector、Secure Tunnel、MCP Proxy、固定 Router。多个项目共享连接，不必每增加一个项目就创建新的 Tunnel 或 Connector。

当前公开 12 个固定工具，用 project_id 选择项目。项目增删不改变工具目录，比为每个项目生成一套不同工具名称更容易维护，也减少外部工具 Schema 同步问题。

Router 根据项目注册表直接执行对应目录的文件操作；桌面端同时管理各项目独立 MCP 进程、端口和日志。不要在视频中画成“所有请求都经过项目 MCP 转发”，这不是当前实现。

### 修改文件前先确认版本

读取文件会得到 SHA-256。编辑时可以带回这个哈希，文件已变化就拒绝按旧版本写入；结构化交接追加强制要求哈希。替换和删除还检查目标片段的出现次数。

修改已有文本前留下备份，再通过临时文件替换原文件。专用交接追加工具使用操作系统文件锁和条目校验。这些机制让冲突能被发现、修改有恢复依据，但不是自动合并，也不是零风险承诺。

### 桌面界面之外的生命周期管理

React/TypeScript 负责 UI，Tauri 2/Rust 负责原生控制和生命周期，Python/FastMCP 实现文件工具。进程管理使用 Windows Job Object，区分单项目停止与全局清理。

启动不只看 PID：还检查端口、就绪标记及 Router MCP HTTP 初始化。日志展示配置路径、文件可读性、初始化阶段和会话信息，帮助判断是配置、程序、端口还是协议环节失败。

### 网络与本机请求分开处理

Direct 不依赖 Magic 端口，也不注入 Magic HTTP 代理参数；Magic 使用配置的本机 HTTP/混合代理。Direct 仍需要有效出网条件，不能宣传成网络不可达时的自动解决方案。

本机 Proxy 与 Router 之间保留 loopback 代理绕行，避免本机通信被系统代理干扰。Public URL 只提供外部 Connector 地址信息，不作为本机启动条件，Doctor 不把公网注册探测混成本机就绪检查。

## 安全边界与安装体验

文件工具限制在用户指定的项目目录，拒绝路径跳转，并检查解析后的路径。Runtime API Key 由 Windows Credential Manager 保管，不写入普通配置；但 ChatGPT 会接收工具读取的内容，不能宣传成文件内容永不离开电脑。

Connector 和固定版本的 MCP Proxy 随安装包交付，发布构建检查运行资源和哈希，用户不必自行安装 Python、Rust 或 Node.js。Tunnel Client 仍需单独提供，外部 Connector 注册与授权也需要用户完成。

项目采用 MIT License，第三方组件保留各自许可证。它不是 OpenAI 官方工具，不提供通用远程桌面、不执行任意系统命令，也不会自动同步不同机器的项目。

## 建议的视频叙事顺序

| 段落 | 讲什么 | 可展示的实际画面 |
| --- | --- | --- |
| 开场问题 | 对话成果需要反复复制、选目录、维护版本 | 一份报告从聊天进入本机文档的过程 |
| 产品定位 | ChatGPT 到本机项目文件的受控桥接 | DCFC 首页和项目目录配置 |
| 核心演示 | 保存、读取、追加，多项目显式路由 | 工具参数与文件实际落盘位置 |
| 技术亮点 | 固定工具目录、文件哈希、生命周期、诊断 | 架构图、冲突拒绝、备份与组件日志 |
| 边界与开源 | 依赖条件、权限范围、候选状态、参与方式 | 公开仓库、配置向导和许可证 |

演示应使用示例项目和不含敏感信息的文件。出现错误、端口监听或待启动页面时保留真实状态，不用静态图冒充成功。只有真实验证后，才能将外部调用描述为已完成。

## 适合结尾的概括

DCFC 的重点，不是再做一个聊天窗口，而是把 ChatGPT 的内容能力接到实际项目文件上：项目选择清楚、写入范围明确、修改前确认版本，连接出错时有具体诊断可查。

0.1.6 的源码、候选安装包和本机回归已经准备，但 Direct/Magic 最终真机端到端验收仍待完成。分享可以展示已实现的能力，同时邀请用户提交脱敏问题、改进安装体验和补充测试，不能宣称所有环境都已稳定运行。
